# 贪吃蛇 · 云对战

经典贪吃蛇 + 通信/网络数字技术改造：**云端权威判定、WebSocket 20Hz 实时同步、客户端帧间插值、AI Bot、RTT 时延测量**。

## 技术点映射

| 题目要求 | 本项目落点 |
|---|---|
| 云计算 | 移动、碰撞、吃食、击杀归属、尸体掉落全部在服务器裁决（云端权威），浏览器只是"瘦客户端"，只上报输入、只渲染快照 |
| 实时通信（5G 低时延场景） | WebSocket **20Hz** 全量状态快照（实测 19.9Hz）+ 客户端按 1.05 帧缓冲做帧间插值，渲染 60fps 不卡顿；客户端每秒 ping 测 RTT |
| AI 算法 | 3 个 Bot：洪泛填充评估可达安全空间（`free_space`）+ 贪心趋近食物 + 规避其他蛇头 + 冲刺决策，会抢食、会避险 |
| 可扩展：推流/观战 | 架构按"服务器推状态流"设计，增加一个只读频道即为直播观战 |

## 玩法

- **双人同屏**：加入页填上"玩家2昵称"即可一键盘双人——玩家1 `WASD` + `空格`/`左Shift` 冲刺，玩家2 方向键 + `回车`/`右Shift` 冲刺；镜头自动取两条蛇的中点并按间距缩放。玩家2昵称留空则回到单人模式（两套按键都有效）
- **加速冲刺**：速度 10 格/秒 → 20 格/秒；代价是每 3 次移动消耗 1 节身体，消耗掉的节掉在地上变成食物（长度低于 8 节无法冲刺）
- **撞身即死**：撞墙、撞到别人的蛇身即死；头对头相撞两败俱伤
- **击杀归属**：把别人撞死计入你的击杀数，排行榜显示 `☠` 数
- **死亡惩罚**：尸体整条化为食物供人抢食，得分清零（最高纪录 `best` 保留）
- **金食物**：每 14 秒刷新 1 个，计 5 分并一次长 5 节
- **暂停**：`ESC` / `P` 冻结整局（逻辑帧、Bot、冲刺消耗全停），任何人按都能暂停/继续，浮层显示是谁按的
- **跟随镜头**：单人视口随蛇头移动，蛇越长视野越广；双人同屏取两蛇中点

## 运行

```bash
pip install websockets
python server.py
```

然后浏览器打开 **http://localhost:8001**，输入昵称加入。

- 多开几个浏览器窗口（可用 `http://localhost:8001?name=张三&name2=李四` 区分）即可联机对战
- 同一页面也可双人同屏（一个键盘）：`name2` 参数即玩家2
- 服务器自带 3 个 AI Bot 陪玩
- 断线自动重连；右上角排行榜实时更新；底部显示实测 RTT 与同步频率

## 协议（JSON over WebSocket）

- 客户端 → 服务器
  - `{"type":"join","name":"...","name2":"..."}`（`name2` 可选，带上即双人同屏，一个连接两条蛇）
  - `{"type":"dir","dx":1,"dy":0,"slot":0}`（`slot`：0=玩家1，1=玩家2；缺省 0）
  - `{"type":"boost","on":true,"slot":0}`
  - `{"type":"pause","on":true}`（暂停期间服务器忽略 `dir`）
  - `{"type":"ping","t":<客户端时间戳>}`
- 服务器 → 客户端
  - `{"type":"welcome","id","ids":[...],"color","colors":[...],"grid","tick_rate"}`（`ids`/`colors` 为本连接全部蛇）
  - `{"type":"pong","t":<原样回传>}`
  - `{"type":"state","tick","grid","tick_rate","paused","paused_by","players":[...],"food":[...],"events":[...]}`
    - 暂停中推流降为 5Hz 心跳，仅用于让新加入/重连的客户端拿到 `paused` 状态
    - `players[]`：`id / name / color / alive / score / best / kills / deaths / bot / len / boost / respawn_in / body`
    - `food[]`：`{x, y, kind}`，`kind` 为 `normal` 或 `gold`
    - `events[]`：`join / leave / eat / die / kill / gold`

## 实现要点

**逻辑帧率必须按绝对时间对齐。** Windows 的默认定时器精度约 15.6ms，`asyncio.sleep(1/20)` 会被抬到下一个时间片边界变成 62.5ms，20Hz 实际只有 16Hz（改造前标称 12Hz 实际约 10.7Hz）。服务器因此：
1. 启动时用 `timeBeginPeriod(1)` 把定时器精度提到 1ms；
2. 逻辑帧按 `next_at += TICK` 的绝对时间轴睡眠，不让误差逐帧累积。

**渲染平滑靠插值，不靠提高同步频率。** 客户端缓存最近 12 帧快照，用 `now - 插值缓冲` 作为渲染时刻，在两帧快照之间按身体下标插值——新快照第 i 节就是旧快照第 i-1 节，整条蛇因此逐帧向前滑动，而不是 20Hz 一跳一格。

插值缓冲是延迟与平滑度的唯一权衡点：缓冲必须 ≥ 一个快照间隔（20Hz 下 50ms）才能连续插值，低于它会一卡一跳。这里取 **1.05 帧 + 8ms**（≈60ms），只留最小安全余量；快照迟到时临时加大、之后缓慢回收。缓冲开大（例如 1.5 帧 + 20ms = 95ms）画面上一样平滑，但会白送近 100ms 输入延迟。

**输入延迟的构成与下限。** 网格蛇只能在"移动帧"换向，而移动是每 100ms 一次，所以服务器端转向延迟天然是 50~100ms（平均 75ms，随按键落在移动周期的相位而定）。客户端感知延迟 ≈ 这段 + 插值缓冲 ≈ 110~160ms。要再往下压只有两条路：客户端预测（本地先动、服务器回滚校正），或把网格移动换成连续移动。

**暂停要同时冻结逻辑帧与墙上时钟。** 重生计时和金食物计时用的是 `time.time()`，暂停时它照样在走；直接停帧的话，一解除暂停所有等待重生的蛇会瞬间满血复活、金食物也立刻补刷。所以恢复时把每个 `respawn_at` 和 `last_gold` 整体后移暂停时长（`set_paused`），快照里的 `respawn_in` 在暂停期间也改用暂停那一刻的时间来算，倒计时不会空转。

**音效为 WebAudio 实时合成**（振荡器 + 噪声缓冲），不含任何音频文件，断网也能响。
